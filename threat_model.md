# MiraiLens Threat Model (Phase 4 Security + Action Governance)

## System Architecture and Trust Boundaries

MiraiLens operates on a three-tier architecture:
1. **AI Client / LLM Agent**: Interacts with the user and proposes actions. **(Untrusted)**
2. **MCP Server (`mcp-server-mirailens`)**: Relays commands between the AI client and the browser extension. **(Untrusted)**
3. **Chrome Extension**: The authoritative executor in the browser. Handles policy, storage, and visual confirmations. **(Trusted)**

```
+------------+        +---------------+        +------------------+
| AI Client  | -----> |  MCP Server   | -----> | Chrome Extension |
| (Untrusted)|        |  (Untrusted)  |        |    (Trusted)     |
+------------+        +---------------+        +------------------+
                                                        |
                                                        v
                                               +------------------+
                                               |   Browser Tab    |
                                               | (Web Page DOM)   |
                                               +------------------+
```

## Threat Vectors & Mitigation Strategy

### 1. Compromised or Adversarial AI Client (Prompt Injection)
* **Threat**: A web page contains prompt injection payloads that trick the LLM client into proposing malicious actions (e.g., clicking a hidden "Delete Account" button or typing payment info into an attacker-owned input).
* **Mitigation / Guarantee**: 
  * The Chrome Extension is the final policy enforcement point.
  * Before any consequential action (`click`, `type`, `navigate`) is executed, the extension inspects the target elements and evaluates local policy rules.
  * Rules default to **fail-closed**. Blocked domains trigger an immediate terminal `BLOCKED` state.
  * Form submissions on draft-only mode and interactions on sensitive fields trigger immediate policy blocks (`ALWAYS_DENY`) or visual overlay approvals (`ALWAYS_ASK`).
* **Honest Limitation**: **Prompt injection is NOT fully solved by MiraiLens**. A sophisticated prompt injection can still trick the LLM into generating malicious instructions. However, MiraiLens guarantees that the LLM *cannot execute* those instructions without explicit human confirmation.

### 2. Confused Deputy & Page Script Spoofing
* **Threat**: An active page script attempts to spoof the approval click on the overlay, or trigger synthetic events to bypass authorization.
* **Mitigation / Guarantee**:
  * **Shadow DOM Encapsulation**: The visual confirmation overlay is built inside a closed Shadow Root (`#mirailens-preview-overlay`). Page scripts cannot traverse the shadow root to click buttons or modify the UI.
  * **Single-use Tokens**: Every confirmation overlay generates a single-use token (`actionId`). Background page execution requires this token on return. Once resolved, the token is invalidated immediately.
  * **Trusted Events**: Human takeover detection relies on verifying `event.isTrusted` inside [content.js](file:///c:/Users/Sachi/Documents/GITHUB/mugenkyou/mcp-server-mirailens/extension/content.js). Synthetic clicks generated by scripts will not reset control state.

### 3. Policy Tampering / Modification Bypass
* **Threat**: The LLM agent tries to modify the domain lists or toggle Draft-Only mode to execute actions silently.
* **Mitigation / Guarantee**:
  * The `set_policy` MCP tool is handled by the extension.
  * Changing any policy parameter requires explicit, physical human approval on the tab overlay. The agent cannot modify policy parameters silently.

### 4. Credential Theft and Data Leaking
* **Threat**: The agent types credentials into standard forms, leaking password or payment card data into logs or console outputs.
* **Mitigation / Guarantee**:
  * **Automatic Sensitive Field Detection**: Inputs matching credential attributes (type="password", autofill keywords, CVV/card placeholders) are flagged.
  * **Value Masking**: Values typed into sensitive fields are masked as `[Sensitive Value Masked]` in all audit logs, extension messaging, and error logs.
* **Honest Limitation**: MiraiLens does not manage or store credentials directly. We defer credential autofill safety to the browser's native credential manager.

## Security Guarantees summary

| Threat Category | Guaranteed? | Mitigation Mechanism |
|---|---|---|
| Prompt Injection Auto-execution | **YES** | Consequential actions require visual human confirmation or are blocked entirely by local policy. |
| In-Page Script Click Spoofing | **YES** | Closed Shadow Root + Single-use Background Verification Tokens. |
| Programmatic Policy Changes | **YES** | `set_policy` requires explicit human approval overlay confirmation. |
| Sensitive Credential Logging | **YES** | Automatic field keyword matching and audit value masking. |
| Malicious Page Takeover | **PARTIAL** | Physically trusted interactions (`event.isTrusted`) trigger immediate takeover, but highly dynamic DOM-hijacking requires active user vigilance. |
